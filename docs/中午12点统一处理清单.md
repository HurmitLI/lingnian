# 中午 12 点统一处理清单

> 日期：2026-09-02
>
> 原则：开发期间遇到外部账号、费用或真人授权就跳过，不让整个任务停住。这里集中列出只有用户能够决定的事项。

## 醒来后先验收，不需要配置任何平台

打开 <http://127.0.0.1:3011/memory>，依次查看：

1. **问问家人**：提一个已有答案的问题，再提一个档案没有记录的问题；确认答案有来源，未知问题可以进入待采访队列。
2. **声音故事**：播放原声并切换故事。
3. **人生轨迹**：检查年份、地点、主题与主题相册。
4. **家人补充**：查看“确认补充、保留为不同记忆、完成家庭核对”。
5. **传家保存**：下载开放格式传承包并解压打开 `index.html`。
6. **影像实验室**：勾选本机整理授权，下载老照片修复、人物讲述或故事情景视频制作包。

## 需要用户决定后才能继续的外部事项

### 1. 人物视频与情景视频供应商

**2026-09-02 进度：首轮人物视频验收不通过。** 已按用户确认短时启动 OneThing 服务 I 区 RTX 4090，使用现有 ComfyUI + LivePortrait 工作流生成 8 秒测试片；但该工作流采用无关驱动视频控制表情，再把旁白音轨后期混入，口型没有受到音频驱动，出现类似咀嚼的嘴部动作，且 8 秒画面无法承载 1982 年完整故事。该片已从公网入口撤下，不能记为人物讲述能力完成。实例已关机，页面显示“未开始计费”。

**2026-09-02 第二次技术尝试：MuseTalk 管线跑通，正式验收仍不通过。** 已按用户确认再次短时启动同一 OneThing RTX 4090。实例自带 ComfyUI 后台被停止后，整段 8 秒输入仍会在人脸关键点预处理阶段一次申请约 15.6 GB 显存并触发 24 GB 显存不足；改为每 2 秒一段后稳定运行。先完成 8 秒技术样片，再将 88.49 秒完整旁白拆为 45 段生成并合并，成片为 512×640、25 fps、H.264 + AAC。检查时发现逐段 AAC 直接拼接会累积编码延迟，已改为给合并后的视频重新封装原始完整旁白，消除中途静音漂移。

最终技术样片已下载并导入本机验收台，Chrome 可完整加载，实播可推进；抽查片头、片尾、多个分段接缝和停顿区间，人物身份及背景稳定，嘴型受音频驱动，停顿时会收口，未出现 LivePortrait 版本持续咀嚼的问题。但该旁白与本机当前选择的《一段愿意留给家人的回忆》尚未完成语义核对，声音清晰度也仍需家人真人听审，因此已在验收台填写原因并驳回，不进入正式展示。页面登记费用为约 ¥0.99（按本次两轮运行时长估算，不等于平台最终账单）；4090 已再次确认“已关机、未开始计费”。

需要选择以下其中一种路线：

- OneThing 云 GPU + ComfyUI，适合后台人工制作与反复复用工作流；
- 按秒计费的视频 API，接入更快，但每次生成直接产生费用；
- 暂不接入，先继续使用本机制作包和零费用快速影像导出。

当前验证实例价格为 0.033 元/分钟。24 GB 显存可以运行 LivePortrait；MuseTalk 对整段输入预处理会超出该实例可用显存，已经验证可以用 2 秒分段规避。本次只完成虚构邀请演示素材，不代表真实家庭人物视频已经开放；后续若把它接入正式任务队列，仍需明确每次生成和月度费用上限。

### 2. ComfyUI 工作流

**2026-09-02 进度：LivePortrait 产品验收不通过；MuseTalk 音频驱动、分段推理、完整合并与原旁白重封装均已跑通。** 88.49 秒技术样片已完成逐帧抽查和 Chrome 实播，证明 24 GB GPU 上可以通过 2 秒分段稳定制作音频驱动人物视频；但它因故事语义未核对和缺少家人真人听审而在本机验收台被驳回。下一次应先把已确认故事、授权照片和对应原声组成冻结素材包，再运行同一分段管线，避免“技术可用但素材对应关系不成立”。

**本机开发已继续完成：** 正式版影像实验室现已具备“登记制作任务 → 导入 MP4 待验收 → 播放检查 → 接受或驳回”的闭环。接受人物视频必须同时通过声音、嘴型、停顿、表情、叙事和时长六项检查；故事情景视频必须通过声音、画面自然度、叙事和时长四项检查。必检项未通过时，后端都会拒绝标记为可用成片；驳回时必须填写具体原因，结果不会进入正式展示。

需要分别提供或确认实际可运行的 API Workflow JSON：

- 老照片修复；
- 照片加原始录音的人物讲述；
- 故事情景视频。

工作流必须在选定 GPU 上完成短样片验证，确认模型文件、节点版本、输入输出节点和显存占用后，才能接入产品任务队列。

### 3. 真人素材授权

- 人物视频：讲述者本人授权照片与原始录音。
- 声音复刻：本人专项声音复刻授权和合法训练样本。
- 老照片：家庭确认拥有使用权；原图永久保留，只生成修复副本。

没有这些授权时，聆年会继续阻止生成，不使用网络上随意获取的真人声音或肖像。

### 4. 公网家庭账号与二维码原声书

真正可扫描的原声二维码需要稳定的私密网址、账号登录、家庭成员权限和媒体访问控制。本机 `127.0.0.1` 地址不能印成二维码；在这些条件确定前，不生成看似可用但实际失效或泄露隐私的二维码。

## 用户不需要处理的事项

数据库迁移、加密兼容、桌面和手机自动化、传承包、本机制作包、文档及中文分支提交由开发流程自动完成。API Key、邀请码、恢复口令和主密钥不会写进本清单或 Git。
