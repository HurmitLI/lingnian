# 「聆年 · 家庭记忆传家宝」技术适配声明

> 文档状态：开发前评审稿  
> 依据：`niannian.md`、`通用技术栈手册.md`  
> 当前动作边界：只完成技术判断与阶段规划，不创建代码、不安装依赖、不初始化仓库、不调用任何模型或外部平台。

## 0. 结论摘要

- 本项目建议拆成 **5 个开发阶段**；另有“第 0 阶段：文档与技术确认”，不计入开发阶段。
- 第一阶段采用 **纵向切片**，先跑通“建一个老人档案 → 触发一个回忆问题 → 录音/上传 → 本地转写 → 人工校对 → 整理草稿 → 人工确认 → 归档到时间线”这一条最小真实链路。
- 第一阶段采用 Web 作为最小交互终端，但只做判断核心体验所需的页面，不等于完整正式前端。
- 结构化数据采用 SQLite + SQLAlchemy + Alembic；音频等大文件保存在本地受控目录，数据库只保存元数据和关联关系。
- 语音转写优先采用本地 FunASR/Paraformer；第一阶段主模型**推荐使用通义千问云 API，并且只用虚构测试文本做真实冒烟**，后端保留可替换适配层。真实家庭资料是否可以发送到云模型，是开发前必须确认的隐私边界。
- 在权限、静态加密和密钥恢复方案未确认并验收前，第一阶段只允许使用虚构资料或明确授权的非敏感测试音频，不录入真实老人档案。
- 声音复刻、照片驱动视频、正式分享、云端部署、老人离世后的权限继承均不属于第一阶段。

## 1. 产品形态判断

- **产品类型与核心任务**：隐私优先、长期积累的家庭口述史与数字记忆 Agent。子女陪伴老人完成建档、回忆触发、语音口述、转写校对、故事归档，最终形成文字回忆录及“视频 + 声音留声”的数字念想。
- **核心用户**：直接用户为老人和子女，间接用户为后代。
- **核心交互**：多轮对话 + 分阶段确认 + 语音/照片输入 + 固定工作流工具调用；模型可以提出问题和整理内容，但不能自行确认史实、删除资料、分享资料或产生付费外部动作。
- **开发路径**：**纵向切片**。
- **选择原因**：录音是否容易、转写是否看得懂、老人是否能跳过、子女是否能校对、确认后能否可靠归档，这些交互直接决定 Agent 是否可用；仅用后台接口或 Swagger 无法验收。
- **当前阶段范围**：只定义第一阶段的最小端到端链路和验收方法，不进入实现。
- **首选最小终端**：本机 Web。PRD 尚未冻结最终发布终端；按手册默认先用 Web 验证，后续再决定正式 Web、微信入口或小程序，避免第一阶段同时建设多个终端。

### 产品事实与技术含义

| PRD 事实 | 技术含义 |
|---|---|
| 家庭隐私、默认不外传、不用于训练 | 数据出本机必须单独获得授权；日志不得记录敏感原文；测试默认使用虚构资料 |
| 跨月跨年积累 | 档案、任务状态、人工确认点必须持久化，服务重启后能恢复 |
| 老人可随时跳过或删除 | “跳过/删除”必须由确定性代码执行；跳过后不得把原话、音频或转写归档 |
| 忠于口述、不编造 | 原始音频、原始转写、人工校对稿、模型整理稿分层保存；模型稿不能覆盖原始证据 |
| 方言和老人语音 | 本地 ASR 先验证普通话/可支持样本；方言准确率必须以真实授权样本验收，不能预先承诺 |
| 照片、声音、视频长期保存 | 大文件与业务元数据分离；需要哈希、格式、来源、归属和备份元数据 |
| 老人离世后向子女开放全部权限 | 属于高风险继承规则，需要身份、授权和审计设计，不在 MVP 中用一个开关草率实现 |

## 2. 采用的默认方案

| 方案 | 采用原因 |
|---|---|
| Python 3.11.x | 符合手册默认基线，也适合 Agent、音频处理和本地 ASR 生态 |
| FastAPI | 将建档、上传、转写、整理、确认、归档做成可独立测试的受控 API |
| Pydantic | 校验接口输入、状态值和模型结构化输出，防止错误数据直接进入家庭档案 |
| pytest | 离线覆盖状态机、解析器、错误路径、文件安全和恢复逻辑 |
| Next.js + TypeScript + Tailwind CSS | 多轮语音与人工校对必须可亲手操作；第一阶段直接做可延续的最小 Web 纵向切片 |
| `/api/v1` | 新项目采用统一且可演进的 API 前缀 |
| 固定流程由代码状态机编排 | “采集 → 转写 → 校对 → 整理 → 确认 → 归档”顺序固定，不交给模型自由规划 |
| 模型/ASR 服务集中在后端服务层 | 前端不接触密钥，模型实现可替换，业务规则不散落到页面中 |
| Git | 开工时初始化并设置 `.gitignore`，保证变更可恢复；本次不初始化 |

## 3. 触发的按需模块

| 模块 | 触发需求 | 第一阶段处理 |
|---|---|---|
| SQLite + SQLAlchemy + Alembic | 档案、人物、故事、时间线、媒体、任务、确认记录之间存在明确关系，且需要迁移与恢复 | **引入**；本地单机数据库，不直接存大音视频 |
| 本地文件资产目录 | 原始录音、标准化音频和后续照片/视频体积较大 | **引入**；受控路径 + UUID 文件名 + 哈希 + 元数据 |
| 本地 FunASR/Paraformer | 中文语音转写与“数据尽量不出本机” | **引入并实测**；具体模型版本在开工时锁定并记录 |
| 音频格式标准化工具 | 浏览器录音格式不统一，本地 ASR 通常需要稳定输入格式 | **引入**；优先 FFmpeg，将副本转为 16 kHz 单声道 WAV，原始音频不覆盖 |
| 持久化任务记录 | 转写和模型整理可能超过普通请求时长，且需要重启恢复 | **引入**；采用“提交任务 + 查询状态 + 获取结果”，暂不引入外部任务队列 |
| 主模型适配层 | 触发回忆、温和追问、忠实整理成文 | **引入接口与 mock**；第一阶段推荐通义千问云 API，用虚构测试文本冒烟；具体稳定模型名在开工时按官方控制台锁定 |
| Chroma / RAG | 长期故事规模扩大后可能需要语义检索 | **暂不引入**；第一阶段用数据库筛选和全文字段即可 |
| OCR | 老照片文字识别 | **暂不引入**；第一阶段不做照片 OCR |
| 对象存储 | 云备份、多设备和正式上线 | **暂不引入**；第一阶段本地保存 |
| 任务队列 | 并发转写、视频合成等长任务 | **暂不引入**；达到并发或可靠性阈值后再评估 |
| SSE | 流式展示模型内容 | **暂不引入**；第一阶段用持久化任务状态更适合转写/整理的可恢复性 |

## 4. 偏离或暂缓的默认方案

| 默认或 PRD 候选方案 | 当前替代/处理 | 原因 | 影响 | 重新评估条件 |
|---|---|---|---|---|
| 默认后端先行 | 改为最小纵向切片 | 语音、跳过、校对和确认本身就是核心能力 | 第一阶段同时需要最小前端，但不会扩展完整视觉系统 | 核心链路验收后扩展正式前端 |
| PRD 中“家庭微信群 / 小程序 / 极简 Web”多种入口 | 第一阶段只做本机 Web | 最终终端尚未冻结，不应并行开发 | 暂时不能在微信/小程序内直接使用 | 正式终端与平台规则确认后 |
| 单进程同步慢操作 | 单进程执行 + 持久化任务状态 | 转写必须可恢复，不能依赖一次长 HTTP 请求 | 单机低并发；不适合多人同时处理 | 出现并发任务、队列堆积或生产 SLA 后 |
| 声音复刻与视频念想 | 暂缓至第四阶段 | 涉及本人授权、费用、外部平台、长任务与冒用风险 | 第一、二阶段只交付文字回忆录方向 | 文字 MVP 和正式交互通过验收，授权与成本确认后 |
| 云备份/云部署 | 暂缓至第五阶段 | 数据敏感、部署形态和长期成本未确认 | 第一阶段仅单机可用 | 本地 MVP 验收、数据迁移与备份策略确认后 |
| 真实老人资料录入 | 第一阶段仅用虚构或明确授权的非敏感测试资料 | 静态加密、身份权限与恢复密钥尚未冻结 | 不能把第一阶段称为真实家庭可用版本 | 第二阶段安全与恢复方案验收后 |

| 加密与密钥恢复 | **待产品决策** | 未确定前只用测试资料；不能用“存在本机”代替静态加密和恢复设计 |

## 6. 需要产品经理决定的问题

以下问题会改变隐私、费用、交付终端或长期可恢复性，不能由技术实现默默代替：

1. **主模型的数据边界**：第一、二阶段是否允许把“经过最小化处理的转写文本”发送给通义千问云 API；若不允许，需要接受本地模型的安装体积、速度和设备限制。
2. **最终首发终端**：正式版本优先 Web、微信入口还是小程序。第一阶段暂按本机 Web 验证，不代表最终发布决定。
3. **加密恢复责任**：家庭档案的恢复密钥由谁保管、丢失后是否允许找回、老人离世后如何转交。这一决定会影响能否长期传承，必须在录入真实资料前确定。
4. **真实数据试用边界**：在安全方案完成前，是否接受第一阶段只用虚构/授权测试资料验收。本文推荐接受。

这些问题不阻碍本次文档交付，但在正式进入开发前需要确认。

## 附录 B：项目阶段总览

> 《通用技术栈手册》规定的是方法和完整旅程，并没有给每个项目固定一个阶段数。结合「聆年」PRD，本项目建议拆成 **5 个开发阶段**。文档确认属于第 0 阶段，不计入开发。

| 阶段 | 名称 | 核心交付 | 进入下一阶段的门槛 |
|---|---|---|---|
| 第 1 阶段 | 核心纵向切片 | 建档 → 一次语音回忆 → 本地转写 → 人工校对 → 忠实整理 → 确认归档 → 时间线可查看 | mock 测试、本地 ASR 冒烟、主模型冒烟（有 Key 时）和人工操作验收通过 |
| 第 2 阶段 | 本地 MVP 完整化与安全硬化 | 家谱/关系、人生阶段题库、照片触发、敏感话题、跨会话记忆、定时提醒、文字回忆录、加密与恢复 | 可使用真实授权家庭资料，本地长期积累与恢复通过验收 |
| 第 3 阶段 | 正式前端与目标终端 | 完整视觉、老人友好语音交互、响应式、错误/中断/恢复体验；确定并完成一个主要终端 | 真机核心任务与无障碍/易用性验收通过 |
| 第 4 阶段 | 视频 + 声音留声 | 授权采集、声音复刻/保真处理、视频合成、长任务、成本与安全提示、下载文件 | 授权、质量、成本、失败恢复和防误用验收通过 |
| 第 5 阶段 | 上线与跨代保存 | 登录权限、备份/迁移、生产存储、监控、部署、分享与继承规则 | 公网/目标环境验收、恢复演练和权限审计通过 |

### 与手册“第 0～5 步”的关系

- 手册的“第 0～5 步”是产品经理的完整操作旅程，共 **6 步**，其中包括交资料、确认声明和上线验收。
- 上表的“5 个阶段”是为「聆年」定制的实际开发阶段。
- 两个数字口径不同：**旅程 6 步，项目开发 5 个阶段**。
