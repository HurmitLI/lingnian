## 用户要求与边界

把整段回忆视为一部影片：同一个人、同一个包、同一时代和空间，动作按前后因果连续发生。不能仅凭“蓝布包”“火车”等关键词独立生成片段。

本次用户授权在自己的 RTX 5080 上更换工作流。仅本机虚构素材试验，不开启 OneThing，不调用收费 API，不上传真实家庭资料，不更换线上入口，不删除旧模型和本机未提交文件。

## Windows 执行步骤

在已有聆年仓库安全拉取本分支；如有无关未提交修改先保留，不 reset、clean 或覆盖。主端维护 generation-worker 的追踪代码，远端不要重复改写这些文件。

1. 确认 ComfyUI 本机地址、模型目录、Python、ffmpeg、ffprobe 路径。检查空闲空间并保留至少 30 GB 余量。模型可放在空间充足的数据盘，保留旧模型。
2. 安装下面三个官方 safetensors（总计 18,144,966,705 字节），允许必要的免费模型下载。使用可续传的 .part 文件；通过 Hugging Face 官方 tree API 的 LFS SHA256 和大小逐项校验，成功后才改为目标文件名。不要下载来源不明的权重或执行模型仓库脚本。
3. 检查 `/object_info` 是否存在 Wan22ImageToVideoLatent、CreateVideo、SaveVideo 等原生节点。若缺失，先记录 ComfyUI 当前提交与本地修改，再做可回退的官方兼容更新；不要覆盖用户自定义节点。检查 SaveVideo 的 mp4/h264 选项和实际模型枚举。
4. 运行 generation-worker 测试。旧云端 worker 不领取新试验任务；实机生成期间避免旧工作流竞争同一个 GPU。若需要暂停，记录原进程与启动方法，试验后按原方式恢复且只保留一个 worker。
5. 使用下方 CLI **先生成一段**（5 秒），输出耗时、原始 MP4、review 拼图与 report。不要直接把它标记通过或上传云端。显存不足先报告实际错误，不降回 SD1.5，不用循环凑时长。
6. 第一段视觉检查后才执行 `--segments 3`，它会复用经过摘要检查的第一段，并用各段真实尾帧作为下一段输入。若第一段人物、年龄或道具不合格，先修参考图/方案，不带着缺陷继续拼长片。

在仓库根目录，使用已安装 worker 的 Python 执行（将占位路径换成实际路径）：

```powershell
& <worker-python> -m lingnian_worker.continuity --plan generation-worker/examples/1982-departure-continuity.json --reference frontend/public/showcase/shen-suqin-station-1982.png --comfy-url http://127.0.0.1:8188 --ffmpeg <ffmpeg-exe> --ffprobe <ffprobe-exe> --segments 1
```

运行产物在 `.worker-data/continuity-trial/<方案摘要>/`，不提交 Git。

## 验收标准

这轮先验证无声画面，不是最终有声成片。完整影片仍需对齐旁白、字幕、镜头时长并逐段试听观看。

- 人物：同一张脸、发型、衣服；年龄与回忆时间对应。现有参考图年龄观感未验收，不能因为保持了脸就算通过。
- 道具：蓝包的轮廓、灰布带、颜色持续相同，不突然出现皮带、绣花或另一个包。
- 叙事：原文是“去无锡”，不是“离开无锡”；未知出发城市不杜撰。
- 年代：不凭空使用黑白滤镜、蒸汽机车或现代高铁。具体车型、服饰未经证实的细节作为演绎保留不确定性。
- 运动：自然动作，不闪烁、不跳变、不靠重复两秒视频凑时长；前段结束姿态接到后段开始。
- 每段必须看原始视频和接缝，拼图仅作辅助。固定种子、参考图和尾帧接续都不是身份一致性保证；失败片段不能进入正式成片。
